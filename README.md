# ivLyrics Overlay for Linux

Linux port of [ivLyrics Overlay](https://github.com/ivLis-Studio/ivLyrics-overlay)
v1.3.2. It keeps the current lyric line, translation and karaoke timing on top
of other windows while Spotify plays.

The UI is React/TypeScript built with Node.js and Vite; the native host is Rust
with Tauri 2 and WebKitGTK. The Linux port adds an X11/XWayland backend for the
window behaviours the upstream build only implemented for Windows and macOS.

## What the Linux port changes

- **Click-through and hover unlock** via the X11 input shape.
- **Always-on-top, dragging and per-monitor full-screen detection** via EWMH.
- **Transparent overlay** with an ARGB visual (requires a compositor).
- **XWayland by default on Wayland sessions.** GTK cannot position a window,
  keep it above others, or make it click-through on native Wayland. If
  `$DISPLAY` exists, the app sets `GDK_BACKEND=x11` before GTK starts.
  Set `IVLYRICS_NATIVE_WAYLAND=1` to opt out; the overlay then renders, but
  click-through, positioning and full-screen detection are unavailable.
- **Optional tray icon.** A missing AppIndicator host no longer prevents the
  app from starting.
- **Linux update path.** Update checks fall back to the GitHub release and pick
  an `.AppImage` asset instead of an `.exe`/`.dmg`.
- **Offline frontend assets** (Font Awesome is bundled by Vite rather than
  loaded from a CDN).

## Install on Arch Linux

Runtime dependencies:

```bash
sudo pacman -S --needed gtk3 webkit2gtk-4.1 libsoup3 libayatana-appindicator \
  librsvg fontconfig
```

### Native package (recommended on Arch)

```bash
sudo pacman -U artifacts/ivlyrics-overlay-1.3.2-1-x86_64.pkg.tar.zst
ivlyrics-overlay
```

The package installs `/usr/bin/ivlyrics-overlay`, the desktop entry and the
hicolor icons. The tray icon needs a StatusNotifier/AppIndicator host: KDE
Plasma provides one; GNOME needs the AppIndicator extension.

### AppImage (portable)

```bash
chmod +x artifacts/ivlyrics-overlay_1.3.2_amd64.AppImage
./artifacts/ivlyrics-overlay_1.3.2_amd64.AppImage
```

The AppImage bundles WebKitGTK and GTK, so it is larger but does not need the
runtime packages above. It still needs a compositor for transparency, and
FUSE 2 to mount itself. If FUSE is unavailable, either install `fuse2` or run
with `--appimage-extract-and-run`.

## Connect it to Spotify

1. Start the overlay and complete the setup wizard.
2. Open ivLyrics inside Spotify → **Settings → General → Desktop Overlay**.
3. Enable **Desktop Overlay** and keep the connection port at `15000` (or set
   the same port in Overlay → **Settings → Advanced → Server Port**).
4. Play a track with synced lyrics in ivLyrics.

Check the local server at any time:

```bash
curl http://127.0.0.1:15000/status
# {"app":"ivLyrics Overlay","protocol":3,"version":"1.3.2"}
```

## Build from source

Arch build dependencies:

```bash
sudo pacman -S --needed base-devel nodejs npm rust pkgconf gtk3 webkit2gtk-4.1 \
  libsoup3 libayatana-appindicator librsvg
```

AppImage:

```bash
npm ci
npm run build:linux          # AppImage in artifacts/
```

Arch package:

```bash
./packaging/build-arch.sh    # source tarball + makepkg, output in artifacts/
```

The PKGBUILD builds the frontend and the Rust binary from source. It expects
the tarball generated by `build-arch.sh`; replace `sha256sums=('SKIP')` before
publishing it.

## Linux limitations

- On a Wayland session the overlay runs through XWayland. Native Wayland
  windows are invisible to X11, so full-screen detection and above-window
  stacking only work for X11/XWayland apps and games (including most Proton
  games). This is a limitation of Tauri/GTK, not of the lyrics pipeline.
- Wayland compositors without XWayland can still display lyrics, but the
  window cannot be made click-through or reliably kept on top.
- The tray icon uses AppIndicator; GNOME requires the AppIndicator extension.
- The upstream release feed has no Linux artifacts. Update checks on Linux
  show the GitHub release page instead of installing an update automatically.

## Layout

```
src/                 React UI and lyric renderer
src-tauri/           Rust/Tauri host, local HTTP server and HTTP sources
src-tauri/src/linux_overlay.rs   Linux X11/XWayland backend
packaging/           PKGBUILD, desktop entry and Arch build script
artifacts/           built AppImage and pacman package (generated)
docs/upstream/       original upstream documentation
```
